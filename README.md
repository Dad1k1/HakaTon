# Обратная связь сотрудников «Модус Трейд»

Локальный многопользовательский кабинет: обращения, рассмотрение, результаты, аналитика, уведомления и администрирование. Next.js + TypeScript, Tailwind CSS, компоненты shadcn/ui, Lucide, PostgreSQL, Prisma, Auth.js/NextAuth Credentials, next-intl. Шрифт Noto Sans поставляется с приложением; внешних запросов для работы интерфейса нет.

**Все 20 исходных обращений вымышлены.** Это демонстрационный набор из предоставленного документа, не реальные сообщения о компании. Роли, сроки, даты и результаты условны. Интернет-хостинг не используется.

## Быстрый запуск

Установите Git и Docker Desktop с Compose v2 (на Linux допустим Docker Engine с Compose v2). Docker должен быть запущен; Windows — режим Linux containers / WSL2. Рекомендуется 4 ГБ доступной памяти и 5 ГБ места. Первой сборке нужен интернет для образов и npm-пакетов; после сборки приложение работает без внешних сервисов.

```bash
git clone https://github.com/Dad1k1/HakaTon.git
cd HakaTon
# macOS / Linux: явная установка с демоданными
./setup.sh --demo
# Без демоданных: ./setup.sh
```

Windows PowerShell:

```powershell
git clone https://github.com/Dad1k1/HakaTon.git
cd HakaTon
.\setup.ps1 -Demo
# Без демоданных: .\setup.ps1
```

Откройте [http://localhost:3000](http://localhost:3000). Логин администратора — значение `ADMIN_LOGIN`, временный пароль — `ADMIN_PASSWORD` из **локального** `.env`. Для демонстрационных пользователей начальный пароль — `DEMO_PASSWORD`; логины и соответствия ролей перечислены в [docs/demo-accounts.md](docs/demo-accounts.md). При первом входе обязательна смена пароля (минимум 12 символов).

### Доступ друга из той же локальной сети

После обновления Docker Compose публикует приложение на сетевых интерфейсах компьютера. В Windows выполните `ipconfig` и найдите IPv4-адрес Wi-Fi или Ethernet, обычно вида `192.168.x.x`. Проверьте сайт на этом компьютере по адресу `http://ВАШ-IP:3000`, затем передайте другу этот адрес. Он должен подключиться к тому же домашнему роутеру. Для защищённых API и входа сервер принимает только localhost и частные IPv4-адреса локальной сети.

Если Windows Firewall блокирует соединение, установите сетевой профиль Wi-Fi/Ethernet в «Частная сеть», затем в PowerShell от имени администратора выполните:

```powershell
New-NetFirewallRule -DisplayName "Modus Trade LAN" -Direction Inbound -Protocol TCP -LocalPort 3000 -RemoteAddress LocalSubnet -Action Allow -Profile Private
```

Это разрешение действует только для TCP-порта приложения и устройств в локальной подсети. Публичный доступ через интернет и проброс порта на роутере для этой настройки не предназначены. Не отправляйте пароль администратора другу: для совместной работы создайте ему отдельную учётную запись.

Скрипты создают `.env` со случайными секретами, собирают образы, применяют миграции и явно инициализируют администратора. Опция `--demo` / `-Demo` дополнительно создаёт демопользователей и импортирует A-001–A-020. Уже существующие пользователи и обращения не перезаписываются. В исходниках нет универсального пользовательского пароля. `.env` нельзя публиковать. При ошибке сборки повторите ту же команду; секреты сохранятся.

### Если `ADMIN_PASSWORD` в `.env` уже изменили

Начальная инициализация создаёт администратора, только когда его ещё нет. Поэтому изменение `ADMIN_PASSWORD` в `.env` после первого запуска само по себе не обновляет пароль в базе. Чтобы сбросить существующую учётную запись администратора, задайте новый уникальный пароль из 16 или более случайных символов в `ADMIN_PASSWORD` и при необходимости логин в `ADMIN_LOGIN`, сохраните `.env`, а затем в PowerShell выполните:

```powershell
docker compose up -d db
docker compose --profile setup run --build --rm reset-admin
```

Команда применяет новый пароль к существующему аккаунту администратора, завершает старые сессии и потребует выбрать личный пароль при следующем входе. Данные обращений, пользователей и файлов остаются в своих volumes. Она откажется менять обычный аккаунт сотрудника. Не используйте пароль, опубликованный в чате; после сброса замените его новым личным паролем.

## Повседневная работа

```bash
docker compose up -d       # запуск, без загрузки демоданных
docker compose stop        # остановка с сохранением данных
docker compose logs -f app # журнал
docker compose down       # удалить контейнеры, сохранить volumes
```

Не выполняйте `docker compose down -v`, если хотите сохранить данные: `-v` удаляет volumes.

База не публикует сетевой порт. Веб-приложение доступно на порту `3000` компьютера, а защищённые API и вход разрешают localhost и частные IPv4-адреса. Пароль передаётся по HTTP без TLS, поэтому используйте только доверенную домашнюю сеть. Публичный IPv4 и проброс порта на роутере не поддерживаются. Приложение и PostgreSQL не нуждаются в API-ключах.

Пять вкладок: «Обзор», «Обращения», «Результаты», «Аналитика», «Настройки». Администратору в настройках доступны пользователи, справочники, маршрутизация и сроки. Роли складываются: собственные обращения + личные назначения + подразделение для руководителя; администратор видит всё. Автор не меняет отправленный текст, а дополняет его комментариями.

Новые обращения получают номера от A-021. Нумерация уникальна и возрастает, но возможны пропуски при откате транзакции — номера не переиспользуются. Открытые обращения считаются просроченными после срока, включая ожидание уточнения. Демонстрационные сроки: 2/5/10 календарных дней для высокого/среднего/низкого приоритета; это не утверждённый регламент.

Статус, история и уведомления изменяются транзакционно. Устаревшая версия карточки получает HTTP 409; обновите карточку перед повтором. Завершённое обращение открывает повторно только администратор с причиной. Первым ответом считается непустой комментарий участника, имеющего право рассмотрения, кроме самого автора. Автоматическое назначение и простое изменение статуса ответом не являются.

## Обновление

Сначала создайте резервную копию. Затем:

```bash
git pull --ff-only
docker compose build
docker compose run --rm migrate
docker compose up -d
```

Обычные запуски и обновления не импортируют демоданные. Для явно выбранного позднего импорта: `docker compose --profile setup run --rm demo`. Если в установке без демоданных уже есть обращения A-021 и выше, номера исходного набора A-001–A-020 остаются свободными. Повторный импорт пропускает существующие номера и сохраняет пользовательские изменения. Удалённые вручную из БД демозаписи при импорте могут быть созданы заново.

## Резервная копия и восстановление

На время копирования остановите приложение, чтобы файлы и БД были согласованы. Для файлов используется одноразовый контейнер сервиса `app`, уже имеющий доступ к volume. Команды одинаковы в bash и PowerShell, кроме синтаксиса перенаправления бинарных файлов: поэтому дамп формируется внутри контейнера и копируется через `docker compose cp`.

Готовые скрипты сохраняют дамп и архив файлов в папку `backups` и не выводят секреты:

```bash
# macOS / Linux
./scripts/backup.sh
# Windows
.\scripts\backup.ps1
```

Скрипты останавливают `app`, делают дамп и архив в `backups/`, запускают приложение обратно. Храните рядом защищённую копию `.env`: в нём параметры подключения и секрет сессий. Папка резервных копий исключена из Git. Данные доступны на этом же ПК даже без интернета.

Восстановление **заменяет** содержимое БД и файлов, поэтому выполняйте его в новой установке или после отдельной копии текущих данных:

```bash
docker compose stop app
docker compose up -d db
docker compose cp ./backups/modus.dump db:/tmp/restore.dump
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner /tmp/restore.dump'
docker compose run --rm --no-deps --user root --entrypoint node -v "${PWD}/backups:/backup:ro" app -e "const fs=require('fs');for(const n of fs.readdirSync('/app/uploads'))fs.rmSync('/app/uploads/'+n,{recursive:true,force:true})"
docker compose run --rm --no-deps --user root --entrypoint tar -v "${PWD}/backups:/backup:ro" app -xzf /backup/uploads.tar.gz -C /app/uploads
docker compose run --rm --no-deps --user root --entrypoint chown app -R node:node /app/uploads
docker compose up -d app
```

## Разработка и проверки

Node.js 22.21+ и PostgreSQL 17. Для локальной разработки настройте `DATABASE_URL` и остальные переменные по `.env.example`. Команды Prisma требуют доступ к официальному `binaries.prisma.sh` при первоначальной загрузке инструментов; Prisma Client использует JS-адаптер PostgreSQL и не скачивает движки во время работы сайта.

```bash
npm ci
npx prisma generate
npm run db:migrate
npm run db:init                 # ADMIN_PASSWORD задаётся локально
npm run db:demo                 # явный выбор; нужен DEMO_PASSWORD
npm run dev
npm run typecheck
npm run test:unit
npm run build
```

Интеграционные и браузерные тесты используют **отдельную БД с именем, оканчивающимся на `_test`**. Все команды ниже выполняйте с `DATABASE_URL`, указывающим на неё, и случайным `NEXTAUTH_SECRET`. Тесты создают свои временные пароли; результаты и файлы лежат в `.local`, не в репозитории.

```bash
npm run db:migrate
npx tsx scripts/test-fixtures.ts
npm run build
npm run start                 # в отдельном терминале с той же тестовой конфигурацией
# затем
RUN_INTEGRATION=1 npm run test:integration
npx tsx scripts/test-fixtures.ts
npx playwright install --with-deps chromium
npm run test:e2e
```

В PowerShell: `$env:RUN_INTEGRATION='1'` перед командой тестов. Если Chromium уже установлен, можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. `npm test` без `RUN_INTEGRATION=1` выполняет только модульные проверки и явно пропускает API-набор. GitHub Actions отдельно проверяет типы, правила доступа, API с PostgreSQL, production-сборку, Chromium и чистую установку через Compose. Секреты CI генерируются на каждом запуске.

Подробности API и архитектуры: [docs/architecture.md](docs/architecture.md). Проверки и известные ограничения: [docs/verification.md](docs/verification.md).

## Границы версии

Нет анонимных обращений, почты, внешнего AI, корпоративного SSO, 1С, Битрикс24 и публичной витрины. Уведомления доступны внутри сайта (опрос раз в 30 секунд). Группировка тем использует повторяющиеся слова заголовков без морфологии и не объединяет записи. DOCX/XLSX проверяются по определённому типу контейнера, но антивирусная проверка не входит в MVP. Язык обращения, имена пользователей и пользовательские названия подразделений сохраняются как введены; системный интерфейс, категории и стандартные подразделения переведены. Размер заявки с файлами ограничен 51 МБ на сервере. При прерывании процесса между сохранением файла и транзакцией может остаться файл без метаданных; он недоступен через API.

### Обновление существующей установки

Перед обновлением сделайте резервную копию по инструкции выше. В папке проекта выполните:

```sh
git pull
docker compose build app migrate
docker compose run --rm migrate
docker compose up -d app
```

Миграция добавляет поля к существующим таблицам и сохраняет обращения и файлы. Не удаляйте volumes и не запускайте демоимпорт для обновления.

### Обсуждения и работа с обращениями

- Автор сообщения может изменить или удалить его; администратор может управлять всеми сообщениями и удалить всё обсуждение после подтверждения. История действий и вложения сохраняются.
- Анонимная подача скрывает имя и идентификатор автора в карточке, списке, комментариях и истории API от других участников. Подразделение видно. Учётная запись хранится в базе для проверки доступа; текст и содержимое файлов система не обезличивает.
- В обсуждение можно перетащить файлы или вставить их из буфера (Ctrl+V / Cmd+V). PNG/JPEG показываются прямо в обсуждении. Существующие ограничения типов, размера и доступа сохраняются. В разделе вложений администратор не видит загрузчик на чужом обращении.
- Заголовок, описание, автор и статус собраны в общей карточке. История и напоминания убраны из интерфейса; рассмотрение раскрывается внизу карточки. Скриншоты находятся только во вложениях и открываются в увеличенном просмотре.
- Обсуждения синхронизируются каждые 5 секунд в активной вкладке. Версии записей продолжают защищать от перезаписи чужих изменений; при конфликте обновите карточку.
- После содержательного ответа автор может завершить собственное обращение с комментарием и оценкой 1–5. Уже зафиксированная реализация сохраняет статус для корректной аналитики.
- Первый вход запускает пошаговую экскурсию с подсветкой меню, формы и кнопки отправки. Её можно пропустить или повторить через «Как пользоваться» в боковой панели. Во время обучения обращения не отправляются. «Больше не показывать» сохраняется в профиле. Настройки разделены на профиль, пароль и администрирование.
- Четыре существующие роли сохранены. Удаление пользователя обратимое: вход запрещается, открытые назначения возвращаются в очередь; история остаётся. Восстановление возвращает учётную запись с её ролью. Правила маршрутизации пропускают заблокированных, удалённых и неподходящих по роли пользователей. Себя и последнего активного администратора удалить или понизить нельзя.

### Аватары профиля

В настройках профиля можно загрузить PNG/JPEG до 5 МБ или удалить аватар. Перед отправкой изображение обрезается по центру и уменьшается до 192×192; оно сохраняется в PostgreSQL. Аватар отображается в обсуждениях, профиле и боковой панели. У анонимного автора фотография скрыта вместе с именем.

Для обновления установки примените миграцию перед запуском нового приложения:

```powershell
git pull origin main
docker compose build app migrate
docker compose run --rm migrate
docker compose up -d app
```

### Логотип и Telegram-уведомления

SVG-логотипы для двух тем находятся в `public/modus-logo-light.svg` и `public/modus-logo-dark.svg`. Сведения об обращении расположены справа внутри общей карточки; на телефоне они переносятся ниже описания. Обзор приветствует пользователя по имени и не содержит ленту изменений.

Чтобы включить Telegram, добавьте в **локальный** `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=значение_токена_вашего_бота
# Необязательно: адрес кабинета, доступный с телефона; пустое значение убирает ссылку из сообщения.
TELEGRAM_APP_URL=http://192.168.1.10:3000
```

Токен не хранится в исходниках. После изменения `.env` примените миграции и запустите фоновый сервис:

```powershell
git pull origin main
docker compose build app migrate telegram
docker compose run --rm migrate
docker compose up -d app telegram
```

Откройте «Настройки → Профиль → Telegram → Подключить Telegram», затем ссылку «Открыть бота» и нажмите «Запустить» в Telegram. Ссылка одноразовая, действует 10 минут; повторное создание отменяет старую ссылку. Чат можно привязать только к одному аккаунту. Отключение доступно в профиле и командой `/stop` в боте.

Сервис `telegram` использует long polling: публичный адрес и входящий webhook не требуются. Одновременно запускается один процесс; второй блокируется блокировкой PostgreSQL. Если бот уже работает через webhook в другом приложении, используйте отдельного бота для этого кабинета. Без токена сервис остаётся в режиме ожидания и не подключается к Telegram. Для разработки: `npm run telegram:worker` рядом с `npm run dev`.

Доставляются только новые уведомления после привязки, на языке профиля и в рамках текущего доступа к обращению. Тексты комментариев и имена авторов в Telegram не передаются: сообщение содержит тип события, номер и заголовок обращения. Удалённые и заблокированные аккаунты пропускаются. Очередь хранится в PostgreSQL, переживает перезапуск и повторяет доставку с задержкой при сетевых ошибках. При блокировке бота связь отключается. При сбое между отправкой и записью результата возможно повторное сообщение. Старые уведомления до привязки не рассылаются.

### Если Telegram не отвечает на /start

Сервис `telegram` теперь запускается автоматически вместе с `app`. После обновления выполните:

```powershell
git pull origin main
docker compose up -d --build app telegram
docker compose logs --tail=50 telegram
```

В журнале должно появиться `Telegram worker connected to @...`. В профиле отображается состояние сервиса: готовность, отсутствие связи, неверный токен или конфликт с другим процессом/webhook. Токен и адреса Telegram API с токеном не записываются в журнал.

Создайте новую ссылку привязки (старая действует 10 минут). Откройте бота и нажмите **«Запустить»**. Если Telegram уже открыл чат без этой кнопки, скопируйте из профиля всю команду `/start КОД` и отправьте её боту. Обычный `/start` без кода не привязывает аккаунт. После привязки нажмите **«Проверить доставку»** в профиле: сайт отправит личное проверочное сообщение в связанный чат.

Заблокированный или недоступный чат больше не останавливает обработку следующих команд. При временных сетевых сбоях команды не подтверждаются до успешной обработки и будут повторены. При конфликте 409 не запускайте дополнительную копию процесса с тем же ботом; проверьте, где он уже используется.
