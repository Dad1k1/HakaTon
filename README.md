# Обратная связь сотрудников «Модус Трейд»

Локальный многопользовательский кабинет: обращения, рассмотрение, результаты, аналитика, уведомления и администрирование. Next.js + TypeScript, Tailwind CSS, компоненты shadcn/ui, Lucide, PostgreSQL, Prisma, Auth.js/NextAuth Credentials, next-intl. Шрифт Noto Sans поставляется с приложением; внешних запросов для работы интерфейса нет.

**Все 20 исходных обращений вымышлены.** Это демонстрационный набор из предоставленного документа, не реальные сообщения о компании. Роли, сроки, даты и результаты условны. Интернет-хостинг не используется.

## Быстрый запуск

Установите Git и Docker Desktop с Compose v2 (на Linux допустим Docker Engine с Compose v2). Docker должен быть запущен; Windows — режим Linux containers / WSL2. Рекомендуется 4 ГБ доступной памяти и 5 ГБ места. Первой сборке нужен интернет для образов и npm-пакетов; после сборки приложение работает без внешних сервисов.

```bash
git clone https://github.com/Dad1k1/HakaTon.git
cd HakaTon
# macOS / Linux: явная установка с демоданными
./setup.sh --demo
# Без демоданных: ./setup.sh
```

Windows PowerShell:

```powershell
git clone https://github.com/Dad1k1/HakaTon.git
cd HakaTon
.\setup.ps1 -Demo
# Без демоданных: .\setup.ps1
```

Откройте [http://localhost:3000](http://localhost:3000). Логин администратора — значение `ADMIN_LOGIN`, временный пароль — `ADMIN_PASSWORD` из **локального** `.env`. Для демонстрационных пользователей начальный пароль — `DEMO_PASSWORD`; логины и соответствия ролей перечислены в [docs/demo-accounts.md](docs/demo-accounts.md). При первом входе обязательна смена пароля (минимум 12 символов).

Скрипты создают `.env` со случайными секретами, собирают образы, применяют миграции и явно инициализируют администратора. Опция `--demo` / `-Demo` дополнительно создаёт демопользователей и импортирует A-001–A-020. Уже существующие пользователи и обращения не перезаписываются. В исходниках нет универсального пользовательского пароля. `.env` нельзя публиковать. При ошибке сборки повторите ту же команду; секреты сохранятся.

## Повседневная работа

```bash
docker compose up -d       # запуск, без загрузки демоданных
docker compose stop        # остановка с сохранением данных
docker compose logs -f app # журнал
docker compose down       # удалить контейнеры, сохранить volumes
```

Не выполняйте `docker compose down -v`, если хотите сохранить данные: `-v` удаляет volumes.

База не публикует сетевой порт. Сайт слушает только `127.0.0.1:3000`. Это версия для работы на одном ПК через локальный браузер; доступ по локальной сети и HTTPS требуют отдельной настройки `NEXTAUTH_URL`, cookie и origin. Приложение и PostgreSQL не нуждаются в API-ключах.

Пять вкладок: «Обзор», «Обращения», «Результаты», «Аналитика», «Настройки». Администратору в настройках доступны пользователи, справочники, маршрутизация и сроки. Роли складываются: собственные обращения + личные назначения + подразделение для руководителя; администратор видит всё. Автор не меняет отправленный текст, а дополняет его комментариями.

Новые обращения получают номера от A-021. Нумерация уникальна и возрастает, но возможны пропуски при откате транзакции — номера не переиспользуются. Открытые обращения считаются просроченными после срока, включая ожидание уточнения. Демонстрационные сроки: 2/5/10 календарных дней для высокого/среднего/низкого приоритета; это не утверждённый регламент.

Статус, история и уведомления изменяются транзакционно. Устаревшая версия карточки получает HTTP 409; обновите карточку перед повтором. Завершённое обращение открывает повторно только администратор с причиной. Первым ответом считается непустой комментарий участника, имеющего право рассмотрения, кроме самого автора. Автоматическое назначение и простое изменение статуса ответом не являются.

## Обновление

Сначала создайте резервную копию. Затем:

```bash
git pull --ff-only
docker compose build
docker compose run --rm migrate
docker compose up -d
```

Обычные запуски и обновления не импортируют демоданные. Для явно выбранного позднего импорта: `docker compose --profile setup run --rm demo`. Если в установке без демоданных уже есть обращения A-021 и выше, номера исходного набора A-001–A-020 остаются свободными. Повторный импорт пропускает существующие номера и сохраняет пользовательские изменения. Удалённые вручную из БД демозаписи при импорте могут быть созданы заново.

## Резервная копия и восстановление

На время копирования остановите приложение, чтобы файлы и БД были согласованы. Для файлов используется одноразовый контейнер сервиса `app`, уже имеющий доступ к volume. Команды одинаковы в bash и PowerShell, кроме синтаксиса перенаправления бинарных файлов: поэтому дамп формируется внутри контейнера и копируется через `docker compose cp`.

Готовые скрипты сохраняют дамп и архив файлов в папку `backups` и не выводят секреты:

```bash
# macOS / Linux
./scripts/backup.sh
# Windows
.\scripts\backup.ps1
```

Скрипты останавливают `app`, делают дамп и архив в `backups/`, запускают приложение обратно. Храните рядом защищённую копию `.env`: в нём параметры подключения и секрет сессий. Папка резервных копий исключена из Git. Данные доступны на этом же ПК даже без интернета.

Восстановление **заменяет** содержимое БД и файлов, поэтому выполняйте его в новой установке или после отдельной копии текущих данных:

```bash
docker compose stop app
docker compose up -d db
docker compose cp ./backups/modus.dump db:/tmp/restore.dump
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner /tmp/restore.dump'
docker compose run --rm --no-deps --user root --entrypoint node -v "${PWD}/backups:/backup:ro" app -e "const fs=require('fs');for(const n of fs.readdirSync('/app/uploads'))fs.rmSync('/app/uploads/'+n,{recursive:true,force:true})"
docker compose run --rm --no-deps --user root --entrypoint tar -v "${PWD}/backups:/backup:ro" app -xzf /backup/uploads.tar.gz -C /app/uploads
docker compose run --rm --no-deps --user root --entrypoint chown app -R node:node /app/uploads
docker compose up -d app
```

## Разработка и проверки

Node.js 22.21+ и PostgreSQL 17. Для локальной разработки настройте `DATABASE_URL` и остальные переменные по `.env.example`. Команды Prisma требуют доступ к официальному `binaries.prisma.sh` при первоначальной загрузке инструментов; Prisma Client использует JS-адаптер PostgreSQL и не скачивает движки во время работы сайта.

```bash
npm ci
npx prisma generate
npm run db:migrate
npm run db:init                 # ADMIN_PASSWORD задаётся локально
npm run db:demo                 # явный выбор; нужен DEMO_PASSWORD
npm run dev
npm run typecheck
npm run test:unit
npm run build
```

Интеграционные и браузерные тесты используют **отдельную БД с именем, оканчивающимся на `_test`**. Все команды ниже выполняйте с `DATABASE_URL`, указывающим на неё, и случайным `NEXTAUTH_SECRET`. Тесты создают свои временные пароли; результаты и файлы лежат в `.local`, не в репозитории.

```bash
npm run db:migrate
npx tsx scripts/test-fixtures.ts
npm run build
npm run start                 # в отдельном терминале с той же тестовой конфигурацией
# затем
RUN_INTEGRATION=1 npm run test:integration
npx tsx scripts/test-fixtures.ts
npx playwright install --with-deps chromium
npm run test:e2e
```

В PowerShell: `$env:RUN_INTEGRATION='1'` перед командой тестов. Если Chromium уже установлен, можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. `npm test` без `RUN_INTEGRATION=1` выполняет только модульные проверки и явно пропускает API-набор. GitHub Actions отдельно проверяет типы, правила доступа, API с PostgreSQL, production-сборку, Chromium и чистую установку через Compose. Секреты CI генерируются на каждом запуске.

Подробности API и архитектуры: [docs/architecture.md](docs/architecture.md). Проверки и известные ограничения: [docs/verification.md](docs/verification.md).

## Границы версии

Нет анонимных обращений, почты, внешнего AI, корпоративного SSO, 1С, Битрикс24 и публичной витрины. Уведомления доступны внутри сайта (опрос раз в 30 секунд). Группировка тем использует повторяющиеся слова заголовков без морфологии и не объединяет записи. DOCX/XLSX проверяются по определённому типу контейнера, но антивирусная проверка не входит в MVP. Язык обращения, имена пользователей и пользовательские названия подразделений сохраняются как введены; системный интерфейс, категории и стандартные подразделения переведены. Размер заявки с файлами ограничен 51 МБ на сервере. При прерывании процесса между сохранением файла и транзакцией может остаться файл без метаданных; он недоступен через API.
