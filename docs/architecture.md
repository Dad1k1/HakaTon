# Архитектура и API

Next.js App Router обслуживает UI и HTTP API. Маршруты Auth.js находятся под `/api/auth`, остальные — `/api/data`. Обращения хранят внутренние enum-коды, время в PostgreSQL — UTC; браузер форматирует даты в своей временной зоне. Переводы интерфейса — `src/messages/{ru,kk,en}.json`, категории имеют три названия в БД. Noto Sans и SVG-иконки поставляются локально. Компонент Button основан на shadcn/ui (Radix Slot, CVA); остальные формы используют доступные HTML-элементы и Tailwind.

## HTTP

Все API требуют актуальной сессии. POST дополнительно проверяет Origin, совпадающий с `NEXTAUTH_URL`. Auth.js защищает вход/выход своим CSRF-токеном. Пароли Argon2id; HttpOnly cookie содержит подписанный JWT с ID и версией сессии. На каждом запросе пользователь перечитывается из БД; блокировка, сброс пароля, изменение прав и пароля отзывают старые сессии. Роль не берётся из клиентского ввода. До смены временного пароля доступны только `me` и `password`.

| Метод      | Путь после `/api/data/`                                                                  | Назначение                                      |
| ---------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------- |
| GET        | `me`, `lookups`                                                                          | Текущий профиль, доступные справочники          |
| POST       | `profile`, `password`                                                                    | Профиль и смена пароля                          |
| GET / POST | `appeals`                                                                                | Список / создание                               |
| GET / POST | `appeals/:id`                                                                            | Карточка / изменение рассмотрения               |
| POST       | `appeals/:id/comments`                                                                   | Комментарий `{body, version}`                   |
| POST       | `appeals/:id/files`                                                                      | Multipart `files` (повторяемое поле), `version` |
| GET        | `files/:id`                                                                              | Приватное скачивание после проверки обращения   |
| GET / POST | `notifications`                                                                          | Список / прочтение `{id?}`; без id — все        |
| GET        | `analytics`                                                                              | Показатели в рамках прав и фильтров             |
| GET / POST | `admin/users`, POST `admin/users/:id`                                                    | Управление пользователями                       |
| GET        | `admin/config`                                                                           | Справочники, правила и сроки                    |
| POST       | `admin/departments`, `admin/categories`, `admin/rules`, `admin/rule-delete`, `admin/sla` | Администрирование                               |

Изменение обращения: `{version, status?, priority?, assigneeId?, dueAt?, reason?}`. Произвольное изменение описания, автора и исходного подразделения не разрешено. Поля проверяются Zod. HTTP 400 — некорректные значения/переход, 401 — нет актуальной сессии, 403 — нет права действия/Origin, 404 — отсутствующая или чужая запись, 409 — конфликт версии или уникального значения, 413 — превышение размера. Ошибка возвращается как `{error: "translationKey"}` без деталей БД.

Фильтры: `q`, `type`, `categoryId`, `departmentId`, `status`, `priority`, `assigneeId` (или `unassigned`), `dueFrom`, `dueTo`, `overdue=true`, `completed=true`, `sort`, `order`, `page`. Поиск: номер, заголовок, описание. Страница — 10 записей. Аналитика использует тот же построитель условия доступа и фильтров. Сортировка enum-приоритета следует LOW/MEDIUM/HIGH; статусы следуют порядку схемы.

## Доступ и транзакции

`visibility` и `canSee` определяют совокупность собственных, назначенных и доступных по подразделению обращений. `canManage` разрешает рассмотрение назначенному, руководителю подразделения и администратору. Переназначение доступно руководителю своего подразделения (только активным обработчикам того же подразделения) и администратору. Эти правила применяются в серверных списках, аналитике, карточках, комментариях, уведомлениях и скачивании файлов.

Обновление блокирует строку через условный UPDATE `WHERE id AND version`, увеличивает версию, записывает историю и уведомления в одной транзакции. При конкуренции один UPDATE проходит, другой возвращает 409. Комментарии и вложения также увеличивают версию. Содержательный ответ фиксируется по первому непустому комментарию обработчика, не являющегося автором.

Правила назначения: категория+подразделение → категория → первый активный руководитель подразделения по стабильной сортировке ID → неназначенное. Заблокированные кандидаты пропускаются. Уведомления получают автор, ответственный и участники обсуждения кроме инициатора; неназначенные обращения адресуются активным администраторам. При чтении уведомлений права проверяются повторно.

Файлы не имеют публичных URL. Имена хранения — UUID, исходное имя используется только как метаданные. Проверяются расширение, фактический MIME/сигнатура, размер и суммарное число. Текстовые файлы — UTF-8 без нулевых байтов. Поток запроса ограничен до разбора multipart. Сбой транзакции удаляет сохранённые ею файлы. Директория в отдельном volume.

## Хранение и импорт

Схема — `prisma/schema.prisma`, SQL-миграции — `prisma/migrations`. Служба `migrate` применяет `prisma migrate deploy` перед запуском приложения. Инициализация и демоимпорт — отдельные команды без автоматического запуска при перезапуске. Исходные записи — `data/dataset.json`, извлечены из предоставленного DOCX, тексты не перефразированы. Инкремент номера PostgreSQL начинается с 21, импорт занимает явные номера 1–20 и не уменьшает последовательность. Изменённые ранее записи не перезаписываются. Учётные записи создаются по уникальному логину, правила демомаршрутизации инициализируются один раз.

Первоначальная установка использует пароли из локальной конфигурации и принуждает их смену. Потерянный пароль администратор сбрасывает в настройках, пользователь затем меняет временный пароль. Начальный пароль из `.env` после изменения не восстанавливает доступ и не применяется повторно при перезапуске. В MVP нет отдельного аварийного восстановления администратора: храните резервную копию и при необходимости управляйте пользователем через доверенный локальный доступ к БД.
